교육 영상 챗봇 — 어떻게 구성할까

교육 영상 시청자의 질문에 답하는 챗봇을 붙인다면, LangChain 까지 가지 않고 어디서 시작할 수 있을까. 노코드 · 검색만 · LLM 직접 호출 · RAG 프레임워크를 나란히 놓고, 두 AI(Claude · Codex)에게 따로 물어 비교했다.

2026-11-05 · 학습 노트

1. 왜 — 무엇이 어려운가
  • 시청자 질문은 보통 메신저 상담 채널로 와서 사람이 답한다.
  • 예상 질문 표는 어느 구성이든 필요하다 — 다만 지식을 늘리는 용도보다 답을 평가하고 빠진 자료를 찾는 시험지로 쓴다.
  • 소프트웨어 매뉴얼은 대개 이미지 위주다. 글 자료만 넣으면 그림 속 내용은 못 읽는다. 비전 입력으로 읽힐 수는 있지만 정확도 검증이 필요하니, 조작법은 글로도 풀어 둔다.
  • 노션 공개 페이지는 자동 수집이 막히는 경우가 있다 — 노션 「내보내기(Markdown)」 가 확실하다.
  • 먼저 메뉴 하나(예: 「그리기」 15쪽 안팎)로 작게 데모를 하고 넓힌다.
2. 무엇으로 — 자료 3종 + 답하는 엔진

챗봇 = 자료 + 답하는 엔진. 구성안끼리 다른 건 엔진뿐이다. 자료 준비는 공통이라 먼저 시작해도 버리는 일이 없다.

자료어디서데모 분량
매뉴얼 글노션 내보내기(Markdown), 그림은 조작 순서 문장으로메뉴 하나, 15쪽 안팎
영상 자막이미 있는 자막 파일(VTT 등)관련 영상 1~2개
예상 질문 표엑셀: 질문 · 답 · 근거 쪽 · 영상 시각 · 언어30~100문항
3. 어떻게 — Claude 안 넷

가벼운 것 → 무거운 것 순. 기간 · 기준 수치는 실측이 아니라 어림 · 목표다.

A. 노코드 SaaS 위젯 구현 거의 0

  • Chatbase · 상담 채널 AI · 노코드 챗봇 빌더에 자료를 올리고 시청 화면에 위젯 스크립트 한 줄.
  • 장점: 바로 데모. 대화 기록 · 통계 화면이 따라온다.
  • 단점: 회원 · 구매 여부 연동이 어렵다, 자료가 외부로 나간다, 월 요금, 「영상 몇 분으로 이동」 같은 화면 연동이 안 된다.

B. FAQ 검색만 (AI 없음) 2~3일

  • 관리 화면에 예상 질문 표를 두고, 질문 칸 → 이미 쓰는 검색 엔진(Meilisearch 등)으로 비슷한 질문 상위 3개를 보여 준다.
  • 장점: 지어낸 답이 없다, 추가 비용 0, 검색 엔진의 언어별 색인을 그대로 쓴다(외국어 질문 → 한국어 자료는 따로 맞춰야 함).
  • 단점: 표에 없는 질문은 못 받는다 — 「챗봇」 느낌은 약하다.

C. 자료를 통째로 LLM 에 넣기 (RAG 없음) Claude 추천 · 데모 1~2일

  • 매뉴얼 글 + 자막 + 예상 질문 표를 통째로 system 프롬프트에 넣고(프롬프트 캐시) LLM 이 답한다. 벡터 DB · 임베딩 · LangChain 없음.
  • 서버 코드는 LLM API HTTP 호출 하나 + 질문 받는 주소 하나 + 화면 질문 칸.
  • 매뉴얼이 이미지 위주면 글 양이 적어, 매뉴얼 전체가 한 번에 들어갈 수도 있다(내보낸 뒤 재 본다).
  • 「자료에 없으면 모른다고 · 상담 채널 안내」, 답마다 근거 쪽 · 영상 시각을 달게 한다. 질문 · 답 로그로 예상 질문 표를 키운다.
  • 단점: 질문마다 API 요금(프롬프트 캐시가 적중하면 줄어든다). 자료가 수백 쪽을 넘으면 D 로 간다.

D. LangChain RAG 1~2주

  • Python 서비스(FastAPI + LangChain/LlamaIndex) + 벡터 DB(Chroma · pgvector) + 임베딩. 기존 웹앱은 앞에서 넘겨주기만.
  • 장점: 자료가 아주 많아져도 필요한 조각만 찾아 넣는다.
  • 단점: 운영할 서비스 · 저장소가 늘고, 작은 자료에는 과하다. 답 품질은 결국 C 와 같은 자료에 달려 있다.
4. 어떻게 — Codex 안 넷

같은 물음을 Claude 결론 없이 Codex 에 따로 물었다. 공수 · 요금은 Codex 추정(요금은 각 서비스 요금표 기준, 바뀔 수 있다).

E. Chatbase 위젯 Codex 데모 추천 · 2~3일

  • 지식원 + 삽입 위젯. 그림 속 조작법을 문장으로 옮겨 넣는다. 요금 Hobby $40/월부터(요금표).
  • 위험: 자료 · 질문 외부 저장, 시청 권한 · 지금 보는 영상 맥락 반영이 어렵다.

F. Dify Cloud 노코드 RAG 2~3일

  • 지식베이스 · 챗봇 · 웹 삽입. 내 LLM API 키를 연결할 수 있다. Professional $59/월부터(요금표).
  • 위험: 무료 플랜 문서 50개 제한, 외부 저장 문제는 같다.

G. 기존 웹앱 + 검색 엔진 + LLM Codex 제품 추천 · 4~7일

  • 시청 권한 확인 → 검색 엔진으로 해당 과정 문서 찾기 → LLM 호출 → 출처 링크와 답. C 에 검색 단계를 끼운 모양.
  • 예상 질문은 지식을 늘리는 용도가 아니라 빠진 설명을 찾는 검증표로 쓴다.

H. LangChain · LlamaIndex 1~2주

  • Claude D 와 같다. 작은 데모에는 공수가 크다는 판단도 같다.
5. 의견 — 추천과 데모 순서

Claude: C — 새 인프라 없이 하루 이틀에 「진짜로 답하는」 데모, 자료는 B · D 로 가도 그대로 쓴다.
Codex: 데모는 E(Chatbase), 제품은 G(기존 스택 + 검색 + LLM).
둘 다 LangChain 은 지금 과하다고 봤다. 갈리는 곳은 데모를 외부 SaaS 로 할지, 처음부터 내 코드로 할지 하나다.

  1. 데모할 메뉴의 노션 페이지를 Markdown 으로 내보낸다
  2. 기획 · 현업이 예상 질문 30~50개를 쓴다 — 질문 · 답 · 근거 쪽 · 영상 시각
  3. 고른 구성으로 질문 칸 + 답 API 를 만들고, 예상 질문으로 자동 채점한다
  4. 개발 서버에서 현업이 직접 물어본다
