고유 사용자 수 — 일별 합 · 월별 합 · 기간 고유가 다른 이유

셋은 모두 「고유 사용자 수」지만 고유를 세는 칸의 크기가 다르다 — 일별은 하루, 월별은 한 달, 기간 고유는 기간 전체. 한 사람이 여러 날 · 여러 달 오면 칸이 작을수록 여러 번 셈이 된다.
아래 예시(3명, 9 ~ 10월)는 앱별 일별 합 11 → 일별 합 10 → 월별 합 5 → 기간 고유 3 이다.

숫자 · 회원 · 날짜는 설명을 위해 지어낸 예시다. 앱 A · B 는 같은 계정으로 로그인하는 서로 다른 프로그램 둘이다.

1. 회원 3명의 접속 달력

2. 숫자 분해 — 무엇이 겹쳐 센 것인가
  1. 11앱별 일별 합 (A 일별 + B 일별)
  2. − 1같은 날 A · B 둘 다 (나 9/5)
  3. 10일별 합 (전체)
  4. − 5같은 달 안에서 여러 날
  5. 5월별 합 = 9월 2명 + 10월 3명
  6. − 2두 달 모두 접속 (가 · 나)
  7. 3기간 고유 (전체)

한 달만 고르면 월별 합과 기간 고유는 같다. 달이 둘 이상이면 여러 달에 온 사람만큼 갈라진다.

3. 앱 A + 앱 B 가 「전체」와 안 맞는 이유

두 앱을 다 쓰는 사람은 A 칸에도 B 칸에도 들어가지만 「전체」에서는 한 번이다. 그래서 A + B 단순 덧셈은 전체보다 크다. 이 겹침은 세는 칸의 크기마다 따로 생긴다.

  • 일별 — 같은 날 둘 다 쓴 날만 겹친다 (예시 1건)
  • 월별 — 같은 달 안에 둘 다 쓰면 겹친다 (나 10월: 2일은 A, 9일은 B → 1건)
  • 기간 고유 — 기간 안에 둘 다 쓰면 겹친다 (나 1명)

칸이 클수록 두 앱을 쓴 사람을 한 번에 묶는다.

4. 세는 규칙
  • 먼저 (칸 시작일, 사용자) 쌍으로 중복을 없앤다 — 칸은 하루 · 한 달 · 기간 전체 중 하나.
  • 남은 쌍의 개수를 더하면 그 칸 크기의 「합」이 된다.
  • 「전체」는 앱을 가리지 않고 사용자 하나로 묶은 뒤 센다. 앱별로 센 값을 나중에 더하면 그만큼 부풀려진다.
  • 날짜 경계는 보는 사람의 시간대로 자른다 — UTC 로 자르면 새벽 접속이 전날로 간다.
-- 일별 합 (전체)
SELECT COUNT(*) FROM (
  SELECT DATE(login_at) AS d, user_id
  FROM login_log
  WHERE login_at >= :from AND login_at < :to
  GROUP BY d, user_id
) t;
-- 월별 합: DATE(login_at) 대신 DATE_FORMAT(login_at, '%Y-%m')
-- 기간 고유: SELECT COUNT(DISTINCT user_id) ...
